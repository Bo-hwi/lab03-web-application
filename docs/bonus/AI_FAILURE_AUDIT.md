## Failure #01 — Browser timer lost the Window receiver

- Provenance: AI-generated default timer adapter in `src/bonus/ghosting.js`, before the 2026-11-12 Playwright verification run. The original default was `{ setTimeout, clearTimeout }`, and the implementation called `timers.setTimeout(...)`.
- Expected: clicking Send keeps the phase in dating for approximately 3 seconds, then changes to self-respect exit with the ignored-message status.
- Observed: the first Playwright browser run failed the ghost-status assertion (one bonus browser test failed; four other browser tests passed). A direct Chromium probe of the original call shape returned `TypeError: Illegal invocation`. Clicking Send caused an immediate self-respect exit with the cancelled status. The failure context was recorded in `test-results` during that run; that directory is ignored and can be regenerated by restoring the original adapter in an isolated copy.
- Cause: browser `Window.setTimeout` was invoked as a method of a plain `timers` object, so its required receiver was lost. Node's timer implementation and injected fake timers did not expose the mismatch.
- Correction: the default adapter now wraps `globalThis.setTimeout` and `globalThis.clearTimeout` in arrow functions, preserving the correct global call context while keeping timer injection for tests.
- Regression: focused bonus Playwright run exited 0 with 2/2 passed; full Playwright run exited 0 with 5/5 passed. `npm.cmd test` passed 23/23; lint and build exited 0. Fix commit: `3f112a1` on `hw3` includes the corrected timer adapter and five-second slide alignment.

The earlier defensive null-timeout guard was added before any observed failure and is not counted. The bonus audit has one genuine observed failure; do not invent further entries.

## Current timeout clarification — 2026-11-12

The original browser timer failure was observed while the timeout was three seconds. The current implementation was subsequently aligned to the slides' five-second requirement. The historic reproduction remains genuine, but the old duration is not the current acceptance value. The new five-second Chromium flow passed in the integrated 8/8 browser run.
